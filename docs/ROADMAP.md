# GlideShell 路线图

> 状态（2026-10-26）：P0 完成；P1 进行中（S2 已有结论，S1 等真机录制，S3/S4 进行中）；P2 内核完成、待真机轨迹校准；P3 首个可运行版本完成。本文是重构期间的唯一规划来源；每完成一个阶段，在「阶段总览」里更新状态并补上实测结论。

## 1. 产品目标（按优先级）

1. **真正的连续交互**（最高优先级）：手指移动多少，画面推进多少；中途停住，画面停住；反向滑动，画面倒退。**只有松手后**才按距离和速度决定完成还是取消。
2. **重构多任务切换**：三指上滑渐进展开窗口总览；三指横滑跟手切换窗口；四指横滑连续切换虚拟桌面。
3. **macOS 式物理反馈**：惯性、阻尼、弹簧回弹、速度阈值、可打断动画。重点是输入与画面同步，不是堆动画。
4. **高度可定制，保持原生体验**：可配置三/四指手势、灵敏度、排除程序；三指轻点中键、三指拖移等功能互不冲突。
5. **轻量、低延迟、稳定**：首发 Windows 11 精确式触摸板（PTP），不装内核驱动；开机启动、异常恢复、一键退回 Windows 原生手势。

## 2. 接手评估（2026-10-26）

旧原型 MissionFlow（现位于 `legacy/`，基线 tag `missionflow-final`）验证了两件关键的事：Raw Input 能拿到 PTP 触点流，DWM 缩略图能做实时窗口飞行。但它不是可扩展的产品骨架。

### 2.1 与目标的差距

| 目标 | 旧原型现状 | 差距 |
|---|---|---|
| 1 连续交互 | 三指上滑跟手、可逆 | 自适应平滑带来 25–90ms 滞后；速度按消息处理时刻计算；手指未抬就自动提交（顶格 120ms、滑动中快甩），违背「松手才决定」 |
| 2 多任务 | 只有三指上滑总览 | 横滑切换窗口、四指切桌面均未开始 |
| 3 物理 | 固定时长 easeOutCubic | 松手速度不传递给动画，动画不可真正打断 |
| 4 定制 | 阈值 JSON 热重载 | 无手势映射、排除程序、三指拖移、冲突规则 |
| 5 稳定 | 托盘常驻 | 无开机启动、看门狗、原生手势回退；日志同步写盘刷屏 |

### 2.2 有实证的根因

- **看不到抬指**：触摸板每个触点都带 TipSwitch（0D/42）和 Confidence（0D/47）按钮位，旧解析器只读 value caps，从不读这两位。PTP 用最后一份报文里 TipSwitch=0 表示抬指，之后通常不再发 cc=0 报文。于是旧代码堆了静默 250/600ms 决断、500ms 宽限、顶格自动提交等兜底——这是「卡住 / 误取消 / 冻结」一类问题的共同来源。（待 S1 真机确认）
- **输入与渲染同在 UI 线程**：ApplyVisual 中位数约 12ms（含同步 `Update()` 整窗重绘），WM_INPUT 排队后成批处理（处理间隔中位数≈0ms，而设备空闲时约 4ms 一份）。
- **坐标未按物理尺寸**：X/Y 各自归一化到 0–1，本机触摸板 124×76mm，横竖同一数值不等距；触发阈值 ΔY>0.02 只有约 1.5mm，三指轻点的抖动就可能误弹覆盖层。
- **常驻开销**：空闲时每份报文（包括单指移动指针）都做一次全屏检测；全屏时每份报文同步写一行日志（旧日志 3647 行里有 3507 行是这一条）。
- **结构**：状态机、手势判断、窗口枚举、布局、动画、绘制全在 1387 行的 `OverlayForm` 里，加 7 个状态标志。目标 2/3/4 都要在「手势 → 动作 → 动画」之间加层次，原结构加不进去。

### 2.3 决策：分层重建（不是推倒重写）

**保留**（迁移到新结构，迁移时补测试）：
- HidP 按 preparsed data 逐字段解析的路线
- 窗口收录规则：cloaked 位含义、Win11 最小化窗口要用 `GetWindowPlacement`、工具窗/owner 过滤
- WinEventHook 最小化瞬间缓存 PrintWindow 快照、亮度方差判空白、PrintWindow 免疫名单
- GNOME workspace.js 式就近布局
- 系统手势注册表编码实证（`ThreeFingerSlideEnabled=0xFFFF` + 方向值）
- `--dump` 窗口收录诊断的思路

**丢弃**：
- `OverlayForm` 的整体结构
- 自适应低通「弹簧」
- 一切静默超时判定、宽限期、手指未抬就提交的逻辑
- WinForms 分层窗口（`Opacity`）+ GDI 每帧绘制
- 线程池定时器帧源（非 vsync 对齐）
- `--simdrag` 脚本曲线（改为录制真实轨迹回放）

**技术栈**：继续 C# / .NET 10。真正的合成由 DWM / DirectComposition 在 GPU 上完成，只要输入热路径零分配，托管代码的性能足够。常驻进程去掉 WinForms 后，再评估 NativeAOT 以降低内存与启动时间。

## 3. 目标架构

```
[输入线程]  消息窗口 + Raw Input（RIDEV_INPUTSINK）
            → 零分配 PTP 解析 → 触点帧 { ScanTime, 触点[id, x/y(mm), tip, confidence] }
                 │ 无锁队列
[Core：纯逻辑，可回放测试]
            手势识别：指数稳定、方向锁定、轻点识别 → 手势事件 { Began/Changed/Ended/Cancelled, 指数, 位移mm, 速度mm/s }
            → 手势仲裁：配置映射、排除程序、冲突规则
            → 交互控制器：Overview / AppSwitcher / DesktopSwitcher（只输出「进度 + 速度」）
            → 物理：速度追踪（ScanTime 最小二乘）、落点预测、带初速度可重定向的弹簧、橡皮筋
                 │ 最新状态快照
[渲染线程]  按合成器时钟取样（DCompositionWaitForCompositorClock / DwmFlush）
            → DirectComposition 视觉树 + DWM 实时缩略图
[系统服务]  窗口目录、快照缓存、虚拟桌面（未公开 COM，按系统版本适配）、前台激活
[平台]      原生手势备份 / 接管 / 还原、开机启动、看门狗进程
```

### 3.1 工程结构

```
GlideShell.slnx
src/
  GlideShell.Core/       纯逻辑：手势识别、仲裁、物理、布局、交互模型（net10.0，禁止 P/Invoke）
  GlideShell.Platform/   Windows 实现：Raw Input、DWM、DComp、虚拟桌面 COM、注册表（net10.0-windows）
  GlideShell/            常驻宿主：托盘、线程编排、配置、控制器装配
tests/
  GlideShell.Tests/      单元测试 + 轨迹回放测试 + 架构守卫测试
tools/
  PtpProbe/              只读探针：打印 PTP 报告描述符、录制与分析输入轨迹
legacy/
  M0/ M1/                旧原型，只读参考，不再加功能
```

### 3.2 约定（所有新代码遵守）

- **单位**：触摸板坐标一律换算成毫米；时间一律用硬件 ScanTime（100µs，处理 16 位回绕），不用消息到达时刻。
- **松手才决定**：完成/取消只在收到抬指信号后判定；手指在板上时画面只跟随，不自动提交。
- **不靠静默猜状态**：没有报文 = 状态不变。确需超时兜底的，只能作为异常恢复路径，并单独记日志计数。
- **依赖方向**：`GlideShell → Platform → Core`；Core 不引用 Windows API（由架构守卫测试强制）。
- **热路径零分配**：输入解析、手势识别、每帧渲染不得分配托管对象。
- **日志**：异步、有界、可分级；热路径只计数不写盘。

### 4.3 P3 结果（2026-10-26，首个可运行版本）

- 宿主 `GlideShell.exe`：托盘（单击开关总览；「暂停」= 一键退回 Windows 原生手势；开机启动；打开配置 / 日志；退出）、Ctrl+Alt+O、配置热重载（`%APPDATA%\GlideShell\config.json`）、日志（`%LOCALAPPDATA%\GlideShell\logs`）、看门狗进程（主进程崩溃后按接管记录还原系统手势）、`--restore-native` 紧急还原。
- 只接管**已实现动作**对应的系统手势：切换窗口 / 切换桌面实现之前，三指左右、四指手势仍归系统。
- 呈现：每块屏一个非分层置顶覆盖层（`WS_EX_NOACTIVATE`，永不抢焦点；展开后由低级键盘钩子处理 Esc / Enter），桌面壁纸缩略图打底（其不透明度兼作背景变暗），窗口全部是 DWM 实时缩略图，渲染线程按合成器时钟（`DCompositionWaitForCompositorClock`）逐帧更新。缩略图跨会话复用，只重注册 Z 序变化的部分。
- 实测（热键冒烟测试 + 截屏，本机显示器实际为 165Hz）：帧间隔 P50 6.1ms / P95 6.2ms（旧原型 60Hz 下 P50 15ms / P95 36ms）；预热首次约 78ms（JIT 与首次注册，已改为启动时静默预热）、之后 5.6ms；展开 / 收起 / 背景变暗 / 标题正常，收起后焦点留在原窗口。
- 还差：真机手势体验；最小化窗口的快照（现在显示 DWM 给出的图标卡片 + 占位）；背景里的桌面图标是否隐藏；多显示器实机验证；输入到上屏延迟的实测（等 S4）。

## 5. P1 技术验证项

### S1 输入语义（需要真机手指，约 10 分钟）

- 状态：**录制工具就绪（2026-10-26），等待真机录制**。
- 工具：`tools/PtpProbe`
  - `record`：专用输入线程 + 消息窗口（RIDEV_INPUTSINK），逐份记录每个触点槽的 ContactId、TipSwitch、Confidence、X/Y，以及 ScanTime、ContactCount、物理按键和到达时刻。按 14 个场景引导，每个场景一个 JSON Lines 文件，默认写到 `artifacts/traces/<时间>/`（已被 git 忽略）。
  - `analyze <目录>`：逐文件统计报告率、成批到达、触摸段（指数变化、落指错开、位移、速度、段内空档、结束方式），并归并成「S1 结论草稿」。
  - `selftest`：注入 1 像素鼠标移动验证消息窗口能收到 WM_INPUT（本机已通过）。
  - 分析逻辑已用合成轨迹验证：分段、ScanTime 回绕、静止空档、触点 ID 复用下的抬指判定。
- 场景（`PtpProbe scenarios` 可列出）：单指自检、三指上滑后抬起、三指上滑后停住、三指快甩、三指中途反向、三指下滑、三指横滑、三指轻点、三↔四指切换、手指依次落下、四指上滑、四指横滑、两指滚动、手掌误触。
- 要回答的问题：抬指是否总有 TipSwitch=0 的报文？按住不动时设备是否停发？报告率与成批到达？轻点与滑动的区分阈值？落指错开多久？手掌误触时 Confidence 的表现？
- 产出：结论写进 `docs/spikes/S1-input-semantics.md`；挑选后的轨迹进 `tests/` 作为 P2 回放夹具。

### S2 原生手势的程序化开关

- 状态：**完成，可以全自动**（详见分支 `claude/spike-s2-native-gestures-8782f9` 的 `docs/spikes/S2-native-gestures.md`）。
- 结论：三指 / 四指手势的生效值在 Explorer（twinui.dll）的设置缓存里，注册表只是持久化层，Explorer 不监听它。正确做法 = 写注册表 + 调设置缓存服务的 `Refresh(SettingId)`（与「设置」应用同一路径），可用 `GetValue(SettingId)` 读回校验。只写注册表、广播 `WM_SETTINGCHANGE`、SPI 回写都无效——这就是旧原型「写了不一定生效」的原因。
- 已落地：`Core/NativeGestures`（设置编号表、只接管绑定方向的接管规划、不覆盖用户改动的还原规划）+ `Platform/NativeGestures`（设置缓存连接、先落盘接管记录再写注册表、读回校验、不可用时降级）。`PtpProbe native` 可只读对照注册表值与生效值。
- 还差：S2 文档第 7 节的手指确认（例如写入后三指上滑是否真的不再出现任务视图）。

### S3 虚拟桌面

- 26300 上 `IVirtualDesktopManagerInternal` 等未公开接口的 GUID 与方法表；能否不触发系统动画直接切换。
- 其他桌面上的窗口（被 cloak）能否通过 DWM 缩略图或 Windows.Graphics.Capture 拿到画面；拿不到时，用上次离开该桌面时的快照。
- 顺便确认：Win11 原生四指切桌面在本机的跟手程度，作为 P5 的对照基线。

### S4 渲染延迟

- 非分层顶层窗口 + DirectComposition 背景 + DWM 缩略图，由渲染线程按合成器时钟更新缩略图属性。
- 测量：输入 ScanTime 到对应帧上屏的延迟、帧间隔分布；与旧原型（P50 15ms / P95 36ms @60Hz）对照。
- 可选：评估未公开的共享缩略图视觉（DComp 视觉形式的缩略图），只作为备选，不进基线。

## 7. 本机测试环境

- 触摸板：ASUS Precision Touchpad（VID 2808 / PID 0218），并行报告模式，每份报文 5 个触点槽，物理约 124.2 × 75.7 mm，ScanTime 单位 100µs，空闲约 250Hz。
- 显示：AMD Radeon 780M，2560×1600，缩放 150%；合成器时钟实测约 165Hz（WMI 报告的 60Hz 不准）。
- 系统：Windows 11 Pro 10.0.26300。
- 系统手势：三指上/下 = 无（自定义模式 0xFFFF），三指左/右 = 切换应用，三指轻点 = 中键（ThreeFingerTapEnabled=4）。
