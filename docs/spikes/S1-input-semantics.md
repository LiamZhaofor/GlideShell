# S1 输入语义（真机录制结论）

> 2026-10-26，用户在本机（ASUS Precision Touchpad，VID 2808 / PID 0218，并行报告模式，5 个触点槽）按 `PtpProbe record` 的 14 个场景录制。
> 轨迹在 `tests/GlideShell.Tests/Traces/`（回放测试夹具），分析：`PtpProbe analyze` / `PtpProbe calibrate`。

## 1. 结论

| 问题 | 结论 | 对设计的影响 |
|---|---|---|
| 抬指是否总有 TipSwitch=0 的报文？ | **是**。46 个触摸段全部以 TipSwitch=0 报文结束；逐触点 121 次抬起都带 TipSwitch=0，没有一次「直接消失」。cc=0 报文只有 12 份，不能依赖它 | 「抬指只认 TipSwitch=0」成立，旧原型的静默超时判定确实没有必要 |
| 按住不动时设备是否停发？ | **不停发**。三指停住 2 秒期间最长空档 6.5ms，全部场景触摸期间最长空档 10.4ms | 「没有报文 = 状态不变」的约定在本机不会被触发，保留作为其他设备的保险 |
| 报告率与成批到达 | ScanTime 间隔 P50 4.0ms（≈250Hz），成批到达最多 2% | 输入线程无需特殊处理 |
| 轻点与滑动的区分 | 三指轻点 5 次：时长 120–152ms，质心抖动最大 0.2mm | 滑动阈值 3mm → **2mm**（更跟手）；轻点 ≤200ms 且 ≤1mm |
| 落指错开多久 | 三指「同时」落下：错开 P50 24ms、P95 92ms（`calibrate` 口径，不含故意依次落指 / 加减指的场景） | 指数稳定窗口 40 → **60ms**；在 40–120ms 之间回放结果完全一致（指数在越过滑动阈值前就已稳定），取低延迟一侧 |
| 快甩 | 速度 336–489mm/s，时长 206–314ms | 投影与弹簧参数无需调整 |
| Confidence 位 | 手掌场景低置信报文 587 份；**其他场景 20 份全部出现在一次快甩里：一根手指落下后约 80ms 内 Confidence=0，之后转为 1** | 见第 2 节 |

## 2. 发现的问题：落指初期的低置信

旧逻辑把出现过 Confidence=0 的触点整个生命周期都当作手掌，这次快甩因此只剩两根「有效」手指，整个手势丢失（14 个场景里唯一没通过的一项）。

PTP 规范里手掌判定是单向的（有效 → 低置信，之后一直低置信）；本机触摸板在落指初期还有反方向的情况（不确定 → 有效）。识别器改为：

- 落指时低置信：暂不计入，转为有效后加入手势；
- 有效过之后变成低置信：按手掌处理到底。

修正后当前参数与校准参数都是 14/14 通过，手掌与两指滚动场景仍然不触发任何手势。

## 3. 采用的参数

`GestureSettings` 默认值：`SlopMm` 2.0、`FingerSettleMs` 60、`TapMaxDurationMs` 200、`TapMaxMoveMm` 1.0（灵敏度「标准」预设同步为 2.0mm；「高」1.5mm、「低」3.0mm）。
`calibrate` 原始建议是 2.0 / 120 / 190 / 0.6：指数稳定窗口取 60ms 的理由见上表；轻点的两项在实测值之上多留了余量（样本只有 5 次）。
